# 契约登记表

> 本页是**服务端接口契约的唯一真理**。实现与它冲突时，以本页为准；本页没写的，
> 就是**还没定**，不要在实现里"先随便定一个"。

## 为什么有这一页

服务端的 CLAUDE.md（铁律四）原本把 `magirecocn-architecture-protocol-document`
指为唯一真理。**那个仓库不存在**——它要么从未建起来，要么在文档统一到本站时被并了
进来而没人改指针。结果是：铁律四指向一个空地址，而 `R2` 这样的待决项编号散落在
代码注释与文档正文里，没有任何一处能查到 R1 是什么、R2 定了没有、谁在等谁。

那种状态比没有规矩更糟：它看起来有规矩。所以把登记表落在这里，与协议正文同仓库、
同一次构建验证，不再有跨仓库指针。

::: tip 这一页只登记「状态」，不重复「内容」
字段与语义写在各自的协议页（[API 服务端](/protocol/api-server)、
[客户端握手](/protocol/client-server)）。本页只回答三个问题:**定了没有、
谁在等它、临时值有没有守卫**。
:::

## 状态标记

| 标记 | 含义 | 实现侧可以做什么 |
|---|---|---|
| ✅ **已定** | 线格式冻结。改动走「先加新字段 → 客户端适配 → 双跑过渡 → 再废旧」 | 照着实现 |
| 📝 **草案** | 形状已写出但未冻结，可能整体推翻 | 可以实现，但**必须受生产守卫管辖** |
| 🚧 **保留** | 明令未定 | **禁止自行发挥**。挡路时来把它定掉，不要在实现里绕过去 |

::: danger 📝 与 🚧 都不得裸奔进生产
草案与保留项的共同危险不是"它们存在"，而是**它们可能不被发现地留在生产里**。
一个只含 `path` 的清单在生产跑得好好的，直到某天需要靠内容哈希做缓存失效，
才发现它从来没有过。

所以凡是 📝 的形状，服务端侧必须挂 [`CNV_DEV_MODE` 生产守卫](/deploy/configuration#cnv-dev-mode-生产守卫-🔒)：
忘了配的后果是**功能不可用（显眼）**，而不是临时值悄悄泄进生产（不显眼）。
:::

### R1 · 协议版本协商 ✅

`/client/init` 请求带 `protocol_versions:[int]`，服务端在交集中选一个回
`protocol_version`；无交集则握手失败（`400 protocol_version_unsupported`），
**客户端不得降级尝试**。缺省视为 `[1]`。详见 [API 服务端协议](/protocol/api-server)。

### R2 · 场景清单形状 ✅

2026-08 定稿，形状见 [`/client/scene-manifest`](/protocol/api-server#client-scene-manifest)。
定稿要点与推导过程见下节；生产守卫随定稿一并撤除。

### R3 · `/page/*` 聚合契约 🚧

**不要照抄上游。** 上游那 93 个端点占 96% 流量，且是"存档单向膨胀"的根源——
`quest/native/resume/check` 平均 5.3 MB，每次都把 1730 条关卡记录整包重传，
没有分页也没有增量（见[上游 API 清单](/protocol/upstream-api)）。

前端这次由我们自己写，**可以改成分页/增量契约，不必继承这个包袱**。也正因为前端
还没成型，现在定这批形状等于替一个不存在的消费者做决定。等前端把「一屏需要哪些
状态」列出来再定。

### R4 · 战斗结算裁定边界 🚧

现有 Android 生态里，战斗结算由客户端算完上报，服务端既无随机种子也无逐回合轨迹，
因而无法复现或校验——伤害、通关、掉落均可伪造。**新服务端不得重建这个洞。**

待定的是"裁定到什么粒度"：逐回合轨迹重放（最严，成本最高）、还是只校验伤害/回合/
耗时相对关卡定义的上界（较松，可实现）。无论选哪个，**掉落必须由服务端裁定**而非
采信上报——这一条不待定。

### R5 · master data 来源 🚧

`quest/native/get` 那份战斗定义本质上是 master data（cards / pieces / enemies）的
一次 join，抓包已把 schema 钉死。但 master data **不进版本库**（铁律三），所以
"它从哪来、怎么版本化、怎么下发"必须先定，R4 与 R3 都压在它后面。

## R2 定稿：清单形状

### 字段

```json
{
  "success": true,
  "scene_id": "story/11011",
  "manifest_hash": "9f8e7d6c…",
  "assets": [
    { "path": "resource/chara/1001/base.moc3", "sha256": "3c0a9b8d…", "size": 412849 }
  ]
}
```

| 字段 | 类型 | 为什么需要它 |
|---|---|---|
| `path` | string | 边缘节点上的 key。客户端把它拼到按 `caps:["resource"]` 选出的节点 base 上 |
| `sha256` | string | **缓存失效判据 + 完整性校验**，见下 |
| `size` | int64 | 调度用（并发与进度），也是下载前一道廉价 sanity check：长度对不上就不必算哈希了 |
| `manifest_hash` | string | 整张清单的哈希，用于跳过重复传输，见[增量](#增量-清单自身也可以不传) |

### 为什么是 `sha256` 而不是 ETag

边缘节点**刻意不发 `ETag`**——S3 的 ETag 是文件 MD5，为了一次清单去读完整棵资产树
算摘要，代价与收益完全不成比例（见[资产分发面](/contributing/server/resource-plane)）。
所以缓存失效的判据必须由清单这一侧给出。

而既然要给，就给 sha256 而不是更便宜的 CRC32/MD5——因为它同时承担**完整性校验**：

::: danger 边缘节点是信任树的最外层
边缘节点持小时级证书、可能是第三方镜像。客户端从它那里取来的字节，必须能对着一个
**由业务节点签发路径下发的**哈希核对。这里抗碰撞有真实的安全意义，不只是防传输错误
——所以是 sha256，不是 CRC32。
:::

### 清单里**不放 URL**

只给 `path`，不给完整 URL。客户端从[签名节点目录](/protocol/client-server#签名节点目录)
里按 `caps` 含 `resource` 选节点。把 URL 钉进清单等于把线路选择固化在一份可能被缓存
很久的数据里，多节点、故障转移、就近接入全都作废。

### `scene_id` 命名空间

```
<namespace>/<id>
```

- `namespace`：`^[a-z][a-z0-9_]*$`，保留取值 `story` `battle` `chara` `ui` `movie` `audio`；
- `id`：`^[A-Za-z0-9_.-]{1,64}$`。

::: warning 服务端必须校验格式，即便当前实现是查表
现在 `scene_id` 只用于查表，不拼进文件路径，所以畸形值不危险。**但契约要钉住格式**
——一旦将来有人改成按约定拼路径（很自然的优化），没有格式校验的 `scene_id` 就是一个
现成的路径穿越入口。在它还不危险的时候把闸设上，比等它危险了再补要便宜得多。
:::

### 增量：清单自身也可以不传

响应里的 `manifest_hash` 让客户端能缓存整张清单：

```json
// 请求带上手里那份的哈希
{ "scene_id": "story/11011", "known_manifest_hash": "9f8e7d6c…" }

// 一致时服务端省掉整张清单
{ "success": true, "scene_id": "story/11011", "manifest_hash": "9f8e7d6c…", "unchanged": true }
```

**服务端不跟踪客户端有什么。** 差集完全在客户端做（它本来就有本地缓存索引），
服务端只回答"这张清单还是不是你手里那张"。这与"边缘节点不理解游戏结构"是同一条
原则：状态留在最靠近它的一侧。

`unchanged:true` 时 `assets` **省略**（不是空数组）——空数组的语义是"该场景不需要
任何资产"，与"你手里那份还有效"完全不同，不能共用一种表示。

### 失败分支

| 状态码 | 错误码 | 含义 |
|---|---|---|
| `400` | `missing_scene_id` | 请求没带 `scene_id` |
| `400` | `malformed_scene_id` | `scene_id` 不符合命名空间格式 |
| `404` | `scene_not_found` | 未知的 `scene_id` |
| `503` | `manifest_unavailable` | 场景清单尚未接入构建管线 |

::: tip 503 而不是空清单
未接入时**明确报错**，不返回 `assets: []`。空清单会被客户端理解为"该场景无需任何
资产"，于是静默进入一个残缺的场景——错误被推迟到最难排查的地方才暴露。
:::

## 改这一页的规矩

- 把某项从 🚧 改成 ✅ 之前，**形状必须已经写进对应协议页**，本页只留状态与索引；
- ✅ 之后再改线格式，走「先加新字段 → 客户端适配 → 双跑过渡 → 再废旧」，
  且要在[契约纪律](/contributing/server/discipline)里登记影响面；
- 📝 转 ✅ 时，记得**撤掉对应的生产守卫**——守卫留着不撤，等于永久禁用一个已经定稿
  的功能，而且没人知道为什么。
